# Спецификации (spec-lite)

**Спека — источник правды о том, что мы строим.** Код делается по спеке; если жизнь не совпала со спекой, меняем спеку (в том же PR), а не молча расходимся. Спека = одна страница, а не документ ради документа: она нужна, чтобы четверо людей и их ИИ-агенты тянули в одну сторону и чтобы из неё же получались сценарий демо и слайды.

## Какие бывают

| Файл | Что это |
|---|---|
| `000-product.md` | Продукт целиком: для кого, ценность, метрика эффекта, сценарий демо на 3 минуты, чего **не** делаем. Заполняется в часы 0–1. |
| `NNN-<slug>.md` | Одна фича/сценарий. Создаётся по [`_template.md`](_template.md). |

Нумерация сквозная: `001`, `002`… Номер не переиспользуется, даже если фичу бросили.

## Когда спека обязательна

- **Нужна:** фича занимает больше ~1 часа, **или** трогает контракт (события чата, API, типы), **или** в ней участвуют 2+ зоны.
- **Не нужна:** багфиксы, стили, рефакторинг внутри одной зоны, правки доков. Такие PR идут без спеки.

Сомневаетесь — пишите; хорошая спека занимает 10–15 минут.

## Жизненный цикл

```
draft ──► approved ──► in-progress ──► done
   └───────────┴────────────┴────────► dropped
```

| Статус | Что значит | Как наступает |
|---|---|---|
| `draft` | Пишется, можно оставлять `TODO` | автор открыл PR со спекой |
| `approved` | Согласована, можно кодить. **Нельзя оставлять `TODO`** | PR со спекой смёржен в `main` (ревью ≤15 мин, обязательно смотрит владелец каждой затронутой зоны) |
| `in-progress` | Идёт реализация | первый PR с кодом по спеке переводит статус |
| `done` | Все acceptance criteria отмечены `[x]` и проверены | последний PR с кодом; автор отмечает AC |
| `dropped` | Отказались; причина в журнале спеки | PR, меняющий статус |

## Как работаем по спеке

1. **Идея → спека.** `/spec <идея>` (команда для Claude) или скопируйте `_template.md` в `specs/NNN-slug.md`. Ветка `spec/NNN-slug`, PR с заголовком `docs(NNN): spec <название>`.
2. **Согласование.** Быстрое ревью. Смотрим: можно ли по этой спеке проверить «готово»? Не противоречит ли контракту? Влезает ли в наше время? Мёрж = `approved`.
3. **Реализация.** Ветка `feat/NNN-<кто>-<что>`, PR с заголовком `feat(NNN): …`. В описании PR ссылка на спеку и отметки по AC. Делаем **только то, что в спеке**. Нужно больше — сначала правим спеку (см. ниже).
4. **Задачи по зонам.** В спеке таблица «кто что делает» — это и есть распределение работы. Не ваша строка — не ваша задача.
5. **Готово (Definition of Done)** для фичи:
   - [ ] все AC отмечены и действительно проверены (тест, или руками по демо-сценарию);
   - [ ] работает в `DEMO_MODE=true` без сети и ключей;
   - [ ] демо-сценарий из спеки прошёл **человек, не писавший код**;
   - [ ] `make check` зелёный, контракт синхронен с обеих сторон;
   - [ ] статус спеки `done`.

## Если реальность разошлась со спекой

| Ситуация | Что делаем |
|---|---|
| Поняли, что AC нереально/не нужно | Правим спеку **в том же PR**, что и код; в журнале спеки строка «что и почему»; в чат — одно сообщение |
| Хочется добавить «заодно» | Не в код. Новая спека или строка в «потом» (`docs/ROADMAP.md`). После feature freeze (час 36) — только багфиксы |
| Меняется контракт | Правим раздел «Контракт» спеки + код обеих сторон в одном PR; ревьюят владельцы фронта и бэка |
| Две спеки противоречат друг другу | Чинит автор более новой; обсуждаем в чате до PR |

## Правила хорошей спеки

- **AC проверяемы.** «Ответ начинает стримиться ≤2 с» — да. «Быстро и красиво» — нет.
- **Демо-сценарий — по шагам**, как будет показываться жюри: что кликаем, что видим, что говорим.
- **Один AC обязан про `DEMO_MODE`** (проверяется линтером): фича работает без сети и ключей.
- **«Вне скоупа» не пустой** — это защита от scope creep.
- Спека короткая: больше одного экрана — режем на две.

## Проверка

`make specs` (входит в `make check` и CI) проверяет форму: метаданные, обязательные разделы, нет `TODO` в согласованных спеках, у `done` все AC отмечены, есть AC про `DEMO_MODE`. Содержание проверяет ревью и `/spec-check`.

## Для ИИ-агентов

Читайте спеку перед кодом, работайте строго в её рамках, отмечайте AC только после проверки — подробности в [`CLAUDE.md`](../CLAUDE.md). Команды: `/spec <идея>` — написать спеку, `/spec-check NNN` — сверить код со спекой.
