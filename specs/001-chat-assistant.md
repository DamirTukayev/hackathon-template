## Проблема и ценность

Пользователь задаёт вопрос по данным партнёра и сразу видит, как ответ печатается, а не ждёт «крутилку». Демо не должно падать из-за внешнего API: при сбое провайдера ответ всё равно приходит.

## Демо-сценарий

1. Открываем приложение: в шапке виден режим (`DEMO MODE` или имя провайдера), в пустом чате — три подсказки.
2. Кликаем подсказку «Какие есть риски?» — сообщение пользователя появляется сразу, под ним индикатор «думает».
3. Ответ начинает печататься по словам, оформлен Markdown (список, **выделение**).
4. На длинном ответе нажимаем «Стоп» — генерация прекращается, уже полученный текст остаётся.
5. Говорим: «если основная модель недоступна, система незаметно переключается на запасную — вот плашка с этим».

## Контракт

`POST /api/chat`, тело `{ messages: [{ role: "user" | "assistant", content: string }] }`, ответ — `text/event-stream`, каждое событие — строка `data: <json>`:

| `type` | Поля | Когда |
|---|---|---|
| `meta` | `provider` | перед первым `delta` — кто отвечает |
| `delta` | `text` | кусок ответа |
| `fallback` | `from`, `reason` | провайдер `from` не ответил (`timeout`, имя исключения) |
| `done` | — | ответ завершён |
| `error` | `message` | обрыв или нет доступных провайдеров |

`GET /api/health` → `{ status, demo_mode, providers[] }`.

Источник правды в коде: `apps/api/app/ai/router.py` ↔ `apps/web/src/features/chat/types.ts`. Новые поля добавлять только опциональными.

## AI: промпт, данные, фолбэк

Системный промпт — `ai/prompts.py`, контекст добавляется из `data/knowledge/*.md` через `ai/rag.py`. Цепочка по умолчанию `anthropic → openai → mock`; `mock` всегда доступен. Золотые ответы для демо — `data/demo_cache.json`.

## Вне скоупа

- Хранение истории между перезагрузками страницы
- Авторизация и мульти-пользовательские чаты
- Tool-calls и структурированный вывод (отдельные спеки)
- WebSocket (SSE достаточно)
